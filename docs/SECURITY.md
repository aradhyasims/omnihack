# Security, privacy and data governance

OWASP ASVS 5.0 was used as the reference. The mapping below is a self-assessment by the developer. **A professional security review and penetration test are still required before production launch.**

## Controls

| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Authorization        | Every protected service function calls `requireActor`, `requireCompetitionPermission`, `requireOrgRole`, `requirePlatformAdmin` or an ownership/assignment check. ## Privacy and data governance

- **Notice:** `/privacy` (a template that legal counsel must review). **Consent:** terms at sign-up, rules at registration, optional media consent, showcase-name consent, and marketing opt-in (off by default).
- **Data minimization:** age is only collected when a competition defines an age requirement. Organizer questions are limited to 20.
- **Access:** judges do not see emails; public certificate verification shows only what is printed on the certificate.
- **Export:** profile → "Download my data" (JSON). **Deactivation:** password-confirmed, revokes sessions.
- **Deletion:** requests go to the privacy contact. Records needed for issued certificates and audit are retained (documented). An automated deletion workflow is future work (LIMITATIONS).
- **Retention policy (recommended defaults):** sessions are purged on expiry; email outbox 90 days; audit log 2 years; competition records for the life of the competition plus a policy-defined period. The worker runs this purge daily (`purgeExpiredData`; periods configurable via `RETENTION_*_DAYS`). Competition records, submissions and certificates are kept.
- **Minors:** age gates are configurable; organizers are responsible for parental consent where required.
- **Recruitment data (RECRUITMENT.md):** talent-pool visibility is opt-in per competition, limited to adults (18+) and withdrawable at any time. Withdrawal deletes the CV and closes open applications. Recruiters are scoped to one company and see only consenting candidates, never judging scores or comments. Email addresses are released only after the company shortlists the candidate. CVs are PDF-only, malware-scanned when ClamAV is configured, and served through 10-minute signed links. Profile views, CV downloads and pipeline changes are audited. Org coordinators can manage openings but cannot view candidates.
- **External providers:** no confidential submission data is sent to any third party in this build.

## Incident response (summary)

See [OPERATIONS.md](OPERATIONS.md#incident-response): triage → contain (suspend accounts, revoke sessions by deleting `Session` rows, rotate `APP_SECRET`, which invalidates all signed links) → assess using the audit log → notify affected users and authorities as required → post-mortem.
